# 2026-10-17: the implementation ontology — everything the two audits commit us to

Status: **plan-of-record** (proposed; awaiting the Chair's R-0..R-6 rulings from the
universal repo's `docs/design/2026-10-17-kb-architecture-audit.md`). It merges:
the universal repo's A-side audit (KB-1..KB-6 defects, R-0..R-6 rulings) and the overlay's
B-side capability audit (`../holon-personal/docs/design/2026-10-17-organism-kb-capability-audit.md`
— §1 inventory, §4 hygiene, §5 decisions). Law 7 governs the doc: **every term binds to a
mechanism** — a file, a command, a test. A term whose mechanism does not exist when its
phase lands is a scope leak, not a TODO.

### P1 — the fence seam (R-0 ruling first)

Defect closed: an employee writes steering kinds into any `class:`/project-ref scope
today (`cli.py:871-881` fences only `emp:`/`dept:`/`org`/pin). Landing shape under the
recommended **hybrid + default-open-read**:

| Write kind → scope | Rule (recommended) |
|---|---|
| any kind → own `emp:` / own `dept:` | employee (today) |
| `fact`/`lesson`/`open_question`/`glossary`/`artifact` → `class:<x>` | employee, **only classes the department performs** (genome: the dept's task classes) |
| same kinds → project ref | employee, **only the work's own `project_ref`** |
| steering kinds → any shared scope (`class:`, project, `org`) | **consolidation or Chair only** (matches every organic writer: plan-review notes + consolidation) |
| reads | unchanged: actor `any`, no scope filter |

Mechanism: `cmd_memory_add` policy + the vocabulary of permitted (kind,scope) pairs;
consolidation path untouched. Guards: employee refused a steering `class:` write;
consolidated `decision` on a class scope still lands; reads unchanged (assert the search
path). If the Chair rules reads fenced instead, R-3 flips to fact promotion — that is
the coupling these two decisions must share.

### P2 — the read surfaces (R-1 + R-4 + R-5 rulings)

New commands, each registered with its actor class and a GENOME/CONTRACT/INTENT row
(law 8, law 7):

1. **`holon recall "<question>"`** — the join surface. Deterministic, stdlib: items +
   episodes + in-memory FTS scan over the resolved skill layers + playbook rubrics
   (list) + gold standards (`work.gold_standard`); budgeted like a bundle section; logs
   recall-vs-use as R-2's sensor. Actor `any`; MCP tool + broker extra. No schema change.
2. **`memory show <id>`** — the lineage reader over the two live relations (supersedes
   back, derived_from, promoted-from).
3. **`holon law show <doc>`** — serves the distribution's docs (`DIST/docs/…`) read-only;

   overlay/instance material is structurally out of reach.

INTENT table rows (law 3): Joined recall, Scope fence, Law surface, External-store
contract. Lint: all four commands resolvable from skills/docs (REF), actor classes
registered (law 8).

### P3 — the dormant-seam contract (R-6 ruling, build only if contract-only adopted)

`docs/CONTRACT.md` gains the two external-store schemas (`entries` for logbook incl. the
`api_version` meta row; `nodes(id,parent_id,item_type,name,status,description)` for
trajectory — taken from `context.py`'s SELECTs, which are today the only definition);
`doctor` checks a present store's version and reports an unknown one; a lint pack proves
the contract's column list matches the code that reads it. No read commands land (they
wait for a writer).

### P4 — organism hygiene + the custom-DB pattern (no kernel ruling)

1. **Husk purge**: delete the zero-byte DBs and bare-name accidents
   (`jobs.db`, `job-intel.db`, `job_intel.db`, `jobs`, `kb`, `kb.sqlite`, `kb.db`,
   `sqlite`, `it1`, `job_intel`, `decisions.db`, `freelance.sqlite`, `freelance_kb.db`,
   `kb.sqlite` — the exact set is enumerated at execution); remove the
   connect-without-write path in `kb.py` (or the routine that touches it) that
   regenerates them.
2. **`pc-audit` check**: an empty-db-file check so they cannot regrow.
3. **The pattern codified**: every new B-side custom DB follows the flight-ledger shape
   (single writer, `--reason`, smoke.yaml, `_org.yaml` `services_offered`) — written into
   the organism's pool-layout reference; never a new `kb.py` fork. The two existing forks
   are **not** unified (rewrite spent twice if the waves land first).
4. **KB-class decision table** (overlay record §4) per migrating pool: capability-rewrite
   (career-pipeline, freelance-agency) · pooled-unit-wrap (architectural-leads, KosmOS) ·
   bridge-as-is (flight-ledger) · stays-B (relationship-crm journals).

### P5 — the bridge, per wave (standing items, no phase yet)

- **flight-ledger → A's `capabilities/logbook`**: the seam is schema-compatible today;
  activation = a writer on an A instance (or stays dormant under P3's contract).
- **memory-wire function banks ↔ `dept:` scopes**: one load-bearing store per function
  after cutover; mapped per wave, not in advance.
- **bridge v2.5 skill injection** (≤2 skills/run by keyword overlap) stays top of the
  B-side queue — the ACP audit rules it the only path that delivers skills to zeroclaw
  bodies; holon skills compete with it only at wave cutover per harness.

## 3. Execution order and gates

```
P0 (any day, tests-first) ──► ledger rows + lint --strict 0/0
   │
   └─ needs no ruling; start on ratification of this record
R-0 ruling ──► P1 ──► R-1 + R-4 + R-5 rulings ──► P2 ──► R-6 ruling ──► P3
   (P1 closes the poisoning path; the read/write fence lands as one seam)
   (R-2's trigger arrives with R-1's sensor + the import's volume)
P4 ── independent, B-side hygiene, this week; its class table feeds the waves
P5 ── rides the ventures migration; nothing in P0-P4 assumes it
```

Gate for claiming done, per item: the guard test fails before and passes after; the lint
and test suites run clean; the register row exists; the affected doc rows (INTENT
mechanism table, GENOME §6, CONTRACT contract sections) exist — that last one is what
makes the ontology verifiable rather than aspirational.
